# FunGut - Group Project

This repository contains the code, data analysis, and documentation for our microbiome group project.

## Project Structure

- `data/raw/` – Our two original, unmodified datasets
  
- `data/processed/` – New data files created after cleaning, filtering, importing, or otherwise changing the raw data. This can include files such as filtered feature tables, denoised sequences, taxonomy assignments, exported .qza or .qzv artifacts, and processed .tsv or .csv files.

- `scripts/` – The notebooks and scripts that perform the analysis. Put files such as .ipynb here. These files should read data from data/raw/ or data/processed/ and save their outputs in the appropriate folder. For example, a notebook might import the raw .qza files, run quality filtering or denoising, and save the resulting artifacts in data/processed/. This is where the code that creates the processed data should live.

- `results/` – The outputs you want to look at or include in the report, such as plots, tables, statistical results, and exported visualizations. This is where figures generated by your notebooks (in the `script` folder) should go.

- `docs/` – Written project materials, such as the README, report drafts, explanations of methods, and notes about the project.

- `src/` – Optional folder for reusable Python functions (.ipynb files) that are needed in multiple notebooks. But honestly I think this might be the least relevant and used folder.

## What I changed in the new repository

The main problem with our previous repository was that we had already committed the large `.qza` file before configuring `.gitignore`. Simply adding the file to `.gitignore` afterwards didn't solve the problem, because Git still had it stored in its commit history.

When i created the new repository, I configured `.gitignore` **before adding any raw data**.

A quick explanation: `.gitignore` is not actually a folder (at least I initially thought it was), but a text file containing a list of files and directories that Git should ignore. If you scroll to the bottom of our `.gitignore` file, you'll find the two lines I added:

```
/data/raw/*
!/data/raw/.gitkeep
```

The first line tells Git to ignore the contents of `data/raw/`, meaning those files won't be included in our commits or pushed to GitHub. The second line makes an exception for `.gitkeep`, so the folder itself can still appear on GitHub.

I also added `.gitkeep` files to the other folders, since you cannot push empty folders to Git.

## Raw data: Everyone needs their own copy!

As previously established, we all need our own copy of the raw data files in JupyterHub.

The `data/raw/` folder on GitHub is basically there to make sure we all use the same folder structure and file paths. This way, when we share notebooks through GitHub, we don't have to keep adjusting the paths to the raw data. That's why it is very important that we load the raw files into that same folder on JupyterHub!

The actual `.qza` and `.tsv` files will be visible in our respective JupyterHub `data/raw/` folders, but not on GitHub.

### Setting up the raw data in JupyterHub

After cloning the repository into JupyterHub, open a Terminal and navigate to the repository:

```bash
cd ~/FunGut
```

Make sure the raw data folder exists:

```bash
mkdir -p data/raw
```

Download the two original files from our course data source or shared location and place them in `data/raw/`.

If you've already uploaded the files elsewhere in JupyterHub, you can copy them into the correct folder using:

```bash
cp /path/to/fungut_forward_reads.qza ~/FunGut/data/raw/
```

and

```bash
cp /path/to/fungut_metadata.tsv ~/FunGut/data/raw/
```

Replace `/path/to/` with the actual location of your files.

To check that both files are there:

```bash
ls -lh ~/FunGut/data/raw/
```

And finally, to verify that Git is ignoring them:

```bash
git check-ignore -v data/raw/fungut_forward_reads.qza data/raw/fungut_metadata.tsv
```

Both files should appear in the output with the `.gitignore` rule `/data/raw/*`.

You can also run:

```bash
git status
```

If you haven't made any other changes, it should say `nothing to commit, working tree clean`.

That's it! We should now all have the same folder structure and be able to work with the raw data locally without accidentally pushing the large files to GitHub.
